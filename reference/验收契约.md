# 验收契约

这份文件定义"什么叫做对了"。所有判据都是**可执行**的：每条对应一个脚本、一个退出码。
不要凭感觉判断，也不要改判据让结果变绿。

---

## 0 一条总原则

> **体积、质量、包围盒全对，也不能证明孔画对了。**

三个实测反例（同一零件）：

| 缺陷 | 体积变化 | 质量变化 | 包围盒 |
|---|---|---|---|
| 少一整面 4 个沉孔 | −0.48% | 0.0% | 完全一致 |
| 正面/反面沉孔对调 | **0** | **0** | 完全一致 |
| 2 个 5mm 深盲孔打成通孔 | +0.07% | 0.07% | 完全一致 |

所以：几何指标只做辅助证据，**唯一能判定的是"逐个孔的直径 + z 起止 + 有几个"**。

## 1 四道门（顺序不可换，前一道不过后面不算数）

| 门 | 脚本 | 判据 | 能抓住 | 抓不住 |
|---|---|---|---|---|
| **G1 图注对账** | `spec_verify.py` | 退出码 0，末行 `问题 0 项` | 漏沉孔、沉孔错面、盲孔打穿、数量不对、孔径不对、多出图注没有的孔 | 图注本身漏读（由 G0 拦） |
| **G2 孔系对 DWG** | `hole_audit.py` | 退出码 0，末行 `问题 0 项` | 孔位偏移、直径与 DWG 不符、沉孔只有单一尺寸 | 图注里有但 DWG 没画的东西 |
| **G3 沉孔面** | `hole_audit.py` 末两行 | 正面组与反面组**不在同一个面** | 只做了一个面的沉孔 | 数量虽对但位置错的极端情况 |
| **G4 沉口深度** | `depth_check.py` | 退出码 0（无 `中间!!`） | 沉口悬在板中间、深度不对 | — |
| G5 体积/质量 | `build` 输出 | 体积差 ≤0.5%，质量差 ≤1% | 整体几何错、漏窗口 | 上面三类缺陷 |
| G6 包围盒/原点 | `spec_verify.py` 第 2 行 | = 图纸总尺寸 × 板厚，`min≈0` | 比例错、没平移回原点 | 内部特征 |
| G7 外形 | 两张面视图 | 两面**互补** | 空件、乱线、整面漏做 | 尺寸级别偏差 |

### G0（前置，不属于四道门）

`drawing_spec.py` 的 `unparsed` 必须为空、`holes` 非空，且**条数等于图纸上的孔标注条数**。
这条是防"漏读"的唯一闸门：漏掉一条图注，后面所有数字都会自洽地错下去，而且错得很有信心。

## 2 G1 到底比什么

`spec_verify.py` 把 `drawing_spec.json` 的每条孔图注，映射到 STEP 里同位置的孔壁圆柱面，
比较三样东西：

| 维度 | 判定 | 例子 |
|---|---|---|
| 数量 | 该图注要求 N 处，几何里有 N 个位置满足 | `16` vs `16` |
| 直径组合 | 一段还是两段；大径是否等于 `cbore_dia` | `φ11 + φ6.6` vs 只有 `φ11` |
| z 起止 | 大径段的起止必须等于 `端面 ~ 端面∓深度` | `0.0~3.4` / `4.6~8.0` |
| 面 | 有 `face:"back"` 的必须在**另一端面** | 正面 `下` / 反面 `上` |
| 通/盲 | 盲孔深度必须等于 `depth` | `φ5 0.0~10.0` |

失败时它直接打印差异，不用猜：

```
2 × φ5 盲孔▽5             2    0    FAIL
    实际 (230.0, 113.5): φ5 0.0~15.0   期望: φ5 0.0~10.0
```

排除项（否则会把外形圆角当孔报）：`12×R20`、`8×R3` 这类过渡圆角，
`15 X 35` 这类腰形槽的端头圆柱面。用图注里的 `other_callouts` 做白名单，容差 0.3mm。

## 3 G2/G3 的判读要点

`hole_audit.py` 逐孔打印 `φ11 0.0~3.4 + φ6.6 3.4~8.0` 这种「直径 + z 起止」，末两行汇总：

```
正面沉孔 4 处 ['下(z=0.0)']   反面沉孔 4 处 ['上(z=8.0)']
```

三条同时成立才算过：

1. **每个沉孔位必须有两个直径**。只出现 `φ11` 一个 = 沉孔被吃成通孔（体积只差 0.3%，看体积永远发现不了）。
2. **大直径段必须贴端面**：`0.0~3.4` 或 `4.6~8.0`。出现 `2.0~5.4` = 沉口悬在板中间，G4 会拦。
3. **正面组和反面组不能落在同一个面**：两行都是 `下` 或都是 `上` = 只做了一个面。

## 4 验收器自己也要被检查

```powershell
& $PY scripts\diagnostics\gate_selftest.py drawing_spec.json out\PART.STEP
```

它拿**正确的模型**做 5 组变异，逐组必须报错：

| 变异 | 必须报出 |
|---|---|
| 原样（对照组） | 问题 0 |
| 盲孔深度 +2mm | 问题 ≥1 |
| 沉孔翻到另一面 | 问题 ≥1 |
| 某条图注数量 +1 | 问题 ≥1 |
| 通孔改成盲孔 ▽5 | 问题 ≥1 |

末行 `[PASS] 验收器是活的`。

换新零件、改了 `drawing_spec.py` 的解析规则、或升级了 SW 之后，都要重跑一次。
**永远返回 0 的检查器比没有检查器更危险。**

## 5 阈值与容差（改之前先想清楚）

| 项 | 阈值 | 出处 | 说明 |
|---|---|---|---|
| 质量偏差 | ≤1% | `run.ps1 part` / `estimate_thickness` | 超过就是几何错，不是板厚错 |
| 体积偏差 | ≤0.5% | 人工比对 | 只作辅助 |
| 孔径容差 | 0.08 mm | `apply_spec.py` | 图注 φ6.8 vs DWG φ6.6 这类差异会在这里暴露 |
| 孔位容差 | 0.3 mm | `spec_verify.py` | 约等于 STEP 导出精度 |
| 沉口贴面容差 | 0.02 / 0.05 mm | `hole_audit.py` | 端面判定 |
| 盲孔深度容差 | 0.2 mm | `spec_verify.py` | |

**不要为了让结果变绿去放大这些阈值。** 它们每一个都是踩过坑之后定的。

## 6 已知会出现的"差异"（不是错，但要写进交付说明）

| 现象 | 原因 | 处理 |
|---|---|---|
| 图注写 φ6.8，DWG 画 φ6.6 | 图纸孔表与图形不一致（φ6.8 才是 M6 标准过孔） | 交付时注明差 0.2mm，等用户确认；确认后把对应孔的 `r:3.3` 改 `3.4` 重跑 |
| 质量比图纸轻 0.05~0.1% | 小圆角（R<5）按折线化处理 | 交付说明里给出偏差百分比 |
| 图注里的"正面"没标 | 不写"反面"就是正面 | 按默认正面处理，并在 `drawing_spec.json` 里留 `face` 字段 |
