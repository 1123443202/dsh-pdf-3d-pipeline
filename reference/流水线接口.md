# 数据格式与脚本接口

命令怎么敲看 `QUICKSTART.md`，判据看 `reference/验收契约.md`。这里只写**中间产物长什么样**，
以及每个脚本的输入/输出——需要改代码或排查数据时看这一页。

```
part.pdf
   ├─ drawing_spec.py ──────────> drawing_spec.json      ← 图注合同（验收基准）
   ├─ pdf2cad2.py ──> plan.json
   │     └─ replay2.ps1 ────────> part.dwg + part.dxf + part.log.txt
   └─ part_from_dxf.py ─────────> PART.part.dxf
          ├─ estimate_thickness.py ──> 标准板厚（stdout）
          └─ part_segments.py ──────> part_segments.json
                 ├─ apply_spec.py ──> 写回 back_counterbores / blind_holes
                 └─ build_from_dwg.ps1 (DwgBuild.cs) ──> PART.SLDPRT / .STEP / .PNG / .build.json
                        └─ views.ps1 ──> PART-后视看z0面.PNG / PART-前视看zmax面.PNG
                               └─ spec_verify / hole_audit / depth_check / make_report
```

## drawing_spec.json（图注合同）

```json
{
  "source": "DEMO-01.pdf",
  "holes": [
    { "count": 2, "dia": 5.0, "through": false, "depth": 5.0 },
    { "count": 4, "dia": 6.6, "through": true,  "cbore_dia": 11.0, "cbore_depth": 3.4 },
    { "count": 4, "dia": 6.6, "through": true,  "face": "back",
      "cbore_dia": 11.0, "cbore_depth": 3.4 }
  ],
  "other_callouts": [
    { "kind": "fillet", "count": 4, "r": 5.0, "raw": "4×R5" }
  ],
  "unparsed": [],
  "total_holes": 10,
  "symbols_found": 9
}
```

| 字段 | 含义 | 谁消费 |
|---|---|---|
| `holes[].count` | 图注数量（"8×"） | `apply_spec`（按数量匹配）、`spec_verify`（按数量核） |
| `holes[].dia` | 通孔/内孔直径 | 同上 |
| `holes[].through` | `true` 通孔，`false` 盲孔 | `apply_spec` → `blind_holes` |
| `holes[].depth` | 盲孔深度（`▽5` 的 5） | 同上 |
| `holes[].face` | `"back"` = 图注写了"反面"，缺省正面 | `apply_spec` → `back_counterbores`；`spec_verify` 判 z 端 |
| `holes[].cbore_dia/cbore_depth` | 沉孔口径与深度（`⌴φ11▽3.4`） | 同上 |
| `other_callouts` | 圆角、腰形槽 | `spec_verify` 用来把"假孔"排除（白名单） |
| `unparsed` | 没读懂的原文 | **非空必须停机** |

`φ`/`⌴`/`▽` 在 PDF 里是**矢量路径**，不是文字：
`φ` ≈ 49 段线闭环（6.9×8.3）、`⌴` = 3 段线的开口 U（约 16×8）、`▽` = 横线 + 向下 V（约 8×8）。
文字先按基线聚行，符号再挂到最近的一行——顺序反了会把上下两行图注粘成一行。

## part_segments.json（几何）

```json
{
  "depth_mm": 8.0,
  "segments": [
    { "t": "line",   "a": [0,0], "b": [200,0] },
    { "t": "arc",    "a": [x1,y1], "b": [x2,y2], "m": [mx,my], "r": 5.0 },
    { "t": "circle", "c": [20, 15],  "r": 5.5, "z0": 0,   "z1": 3.4 },
    { "t": "circle", "c": [20, 15],  "r": 3.3, "z0": 3.4, "z1": 8 },

    { "t": "circle", "c": [100, 60], "r": 3.3, "z0": 0,   "z1": 4.6 },
    { "t": "circle", "c": [100, 60], "r": 5.5, "z0": 4.6, "z1": 8 },
    { "t": "circle", "c": [160, 60], "r": 2.5, "z0": 0,   "z1": 5 }
  ],
  "back_counterbores": {
    "mouth_dia": 11.0, "depth": 3.4,
    "origins": [[100.0, 30.0], [140.0, 30.0], [100.0, 90.0], [140.0, 90.0]]
  },
  "blind_holes": {
    "dia": 5.0, "depth": 5.0,
    "origins": [[160.0, 60.0], [40.0, 60.0]]
  }
}
```

- `t`：`line` / `arc`（三点：起、止、弧上一点）/ `circle`。
- **`z0`/`z1` 是核心**：每个轮廓和圆都带自己的 z 区间，`DwgBuild.cs` 把所有端点排序后自动切带，
  每带只画"整段落在这一带里"的元素。相邻带元素集合相同会自动合并，所以带数不是固定 3 段。
- `back_counterbores` / `blind_holes` 由 `apply_spec.py` 从图注写进来；它们**不在 DWG 里**。
- 圆弧中点必须取 **bulge 的右法向**：`m = 弦中点 + 右法向 × (bulge×弦长/2)`。用左法向会整圈镜像。

## DwgBuild 输出（stdout 最后一行）

```json
{"ok":true,
 "log":["loops=8 through=10 blind=2",
        "back mouths=4 depth=3.4",
        "blind holes=2 depth=5",
        "band z0~3.4 (18个元素) segs=18 -> ok 凸台-拉伸1",
        "band z5~8 (16个元素) segs=16 -> ok 凸台-拉伸4"],
 "files":["…SLDPRT","…STEP","…PNG"],
 "volume_mm3":173559.75}
```

`run.ps1 build` 会：① 要求 `ok:true` 且 `volume>1000`；② 逐行核对 `(N个元素)` 与 `segs=` 相等；
③ 把这份 JSON 存成 `out/PART.build.json` 给 `make_report.py` 用。

## 脚本接口速查

| 脚本 | 命令行 |
|---|---|
| `drawing_spec.py` | `图纸.pdf [drawing_spec.json]`，`unparsed` 非空则非零退出 |
| `pdf2cad2.py` | `图纸.pdf plan.json --part-width 200 --texts dim` |
| `replay2.ps1` | `-PlanPath plan.json -Out x.dwg [-Visible]`，自动 DXFOUT |
| `part_from_dxf.py` | `x.dxf 8 out.dxf [--counterbore 3.4]` |
| `estimate_thickness.py` | `out.dxf 0.47 --material aluminium` |
| `part_segments.py` | `x.dxf part_segments.json 8` |
| `apply_spec.py` | `part_segments.json drawing_spec.json` |
| `build_from_dwg.ps1` | `-Segments … -OutDir … -Name … -CounterboreDepth 3.4 [-KeepOpen]` |
| `spec_verify.py` | `drawing_spec.json PART.STEP`（0 = 全过） |
| `hole_audit.py` | `PART.STEP part_segments.json`（0 = 全过） |
| `depth_check.py` | `PART.STEP`（0 = 无悬空沉口） |
| `views.ps1` | `-Part PART.SLDPRT -OutDir out` |
| `make_report.py` | `--spec … --step … --build-json … --drawing-mass 0.47 --out 验收记录.md` |
| `gate_selftest.py` | `drawing_spec.json PART.STEP`（变异测试） |

## 示例件 DEMO-01 的期望值（虚构件，用来自查流程）

| 项 | 值 |
|---|---|
| 外形 | 200.00 × 120.00 × 8.00（6061-T6，0.0027 g/mm³），原点在左下角 |
| 窗口 | 60 × 30，贯穿 |
| 体积 | 173 559.8 mm³（几何解析值 175 096.3，扣 8 个沉口 1 654.3、补回盲孔 117.8） |
| 质量 | 0.4686 kg（图纸 0.47，−0.30%） |
| 孔位 | 10 处：4 正面 ⌴φ11▽3.4 + 4 反面 ⌴φ11▽3.4 + 2×φ5 盲孔▽5 |
| 分段 | 0~3.4 / 3.4~4.6 / 4.6~5 / 5~8（18/18/18/16 元素） |

**新零件不要照抄这些数字**，只用来自查"流程是否走对"：每带的元素数是不是等于 `segs`，
四个带加起来是不是"轮廓段数 + 该带圆数"，体积差值能不能被沉孔与盲孔两笔解释完。

## 已知差异

- 图纸孔表标 φ6.8、PDF 文字层解析为 φ6.6 的情况很常见（差 0.2mm；φ6.8 才是 M6 标准过孔）。
  脚本按图注读，**交付时要把这 0.2mm 明确告诉用户等确认**，确认后把对应孔的 `r:3.3` 改 `3.4` 重跑。
- 小圆角（R<5）按规则折线化，对体积影响 0.02% 量级——低于判据阈值，但要在验收记录里注明。
